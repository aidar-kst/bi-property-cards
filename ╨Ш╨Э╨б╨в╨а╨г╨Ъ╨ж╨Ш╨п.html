Цифровые визитки BI Property — инструкция

Ничего устанавливать не нужно: всё делается в браузере. Весь процесс займёт 30–40 минут. Вам понадобится компьютер (на телефоне загрузка файлов неудобна).

Как это работает

Вы храните данные сотрудников в одном текстовом файле data/employees.json. После каждого изменения GitHub сам (за 1–2 минуты) пересобирает сайт: для каждого сотрудника создаются страница .../card/имя-фамилия/, файл контакта .vcf и QR-коды в PNG и SVG. Бесплатно, без рекламы и подписок. Стоимость — 0 ₽/₸ (для публичных репозиториев GitHub Pages и GitHub Actions бесплатны).

Важно про приватность. Репозиторий должен быть публичным (иначе бесплатный GitHub Pages недоступен), поэтому телефоны и e-mail из employees.json будут доступны любому, кто откроет репозиторий. Это те же данные, что и на визитке, но убедитесь, что сотрудники согласны. Страницы визиток закрыты от индексации поисковиками, но доступны по прямой ссылке.

Этап 1. Подготовьте файлы

  1. Скачайте ZIP-архив проекта и распакуйте его (правый клик → «Извлечь всё» / двойной клик на Mac).
  2. Внутри будут папки assets, data, tools, .github и файлы README.md, .gitignore, ИНСТРУКЦИЯ.md. Папка .github на Mac может быть скрыта — это нормально, её мы создадим вручную на этапе 3.
  3. Откройте data/employees.json в Блокноте (или TextEdit) и посмотрите на пример: в нём тестовые данные. Позже замените их на настоящие.

Этап 2. Регистрация и репозиторий на GitHub

  1. Откройте github.com → Sign up. Введите e-mail, пароль, имя пользователя (оно станет частью адреса сайта, например bi-property → bi-property.github.io; лучше корпоративное нейтральное имя, его сложно менять), подтвердите e-mail кодом.
  2. Войдите в аккаунт. Нажмите + справа вверху → New repository.
  3. Заполните: - Repository name: cards (коротко, латиницей; от этого имени зависит адрес всех ваших ссылок, поэтому решите сейчас и потом не меняйте); - Public — выбрать обязательно; - Add a README file — не отмечать; - остальное не трогать → Create repository.
  4. На открывшейся странице нажмите ссылку uploading an existing file.
  5. Откройте распакованную папку проекта и перетащите в окно браузера содержимое папок: assets, data, tools (перетаскивайте сами папки целиком) и файлы README.md, .gitignore. Дождитесь окончания загрузки (должны быть видны все файлы, в том числе шрифты .woff2 и ornament.svg).
  6. Внизу нажмите зелёную Commit changes.

Этап 3. Файл автоматической сборки

(Этот файл надо создать через сайт: папка .github часто пропадает при перетаскивании.)

  1. В репозитории: Add file → Create new file.
  2. В поле имени введите точно: .github/workflows/deploy.yml (при вводе / GitHub сам создаст папки).
  3. Откройте в Блокноте файл .github/workflows/deploy.yml из архива (если папка не видна — включите показ скрытых файлов), скопируйте весь текст и вставьте в большое поле на GitHub.
  4. Commit changes → Commit changes.

Этап 4. Включение GitHub Pages

  1. Вкладка Settings репозитория → слева Pages.
  2. В блоке Build and deployment → Source выберите GitHub Actions. (Ветку и папку выбирать не нужно: сборка идёт через Actions, сайт публикуется из dist.)
  3. Перейдите на вкладку Actions. Должен идти (жёлтый кружок) или завершиться (зелёная галочка) запуск «Сборка и публикация визиток». Если запуска нет — откройте его слева в списке и нажмите Run workflow. Подождите 1–3 минуты до зелёной галочки.
  4. Адрес сайта: Settings → Pages (вверху «Your site is live at…») либо в Actions внутри запуска, блок deploy. Он имеет вид https://ИМЯ.github.io/cards/.
  5. Ссылка на визитку: https://ИМЯ.github.io/cards/card/anna-kuzmina/.

Если запуск красный: откройте его, раскройте шаг «Сборка…» — там написано по-русски, в какой записи ошибка (например, забытая запятая в JSON).

Этап 5. Проверка (чек-лист)

На компьютере: - [ ] Ссылка визитки открывается; логотип, орнамент и шрифт отображаются. - [ ] Обновите страницу (F5) — визитка остаётся на месте. - [ ] Откройте ссылку в режиме инкогнито. - [ ] Неверный адрес показывает страницу «Визитка не найдена».

На iPhone (Safari и камера): - [ ] Наведите камеру на QR-код с экрана → открылась визитка. - [ ] Нажмите «Сохранить контакт» → появилась карточка контакта → «Добавить» (или «Создать новый контакт»). - [ ] В контактах: верно имя и фамилия (кириллица тоже), компания, должность, телефон. - [ ] Звонок по номеру на странице открывает набор номера.

На Android (Chrome и камера/Google Lens): - [ ] QR открывает визитку. - [ ] «Сохранить контакт» скачивает файл; откройте его (из уведомления или «Файлы») → приложение «Контакты» предлагает сохранить. - [ ] Проверьте также открытие ссылки из мессенджера (Telegram/WhatsApp): встроенные браузеры иногда ведут себя иначе — тогда выберите «Открыть в браузере».

QR-коды: - [ ] Скачайте PNG и SVG (этап 7), отсканируйте распечатанный на бумаге код 2–3 телефонами с расстояния 20–30 см.

Я не мог проверить работу на реальных телефонах в своей среде, поэтому этот чек-лист обязателен перед печатью тиража.

Этап 6. Добавление и изменение сотрудников

  1. В репозитории откройте data → employees.json → значок карандаша (Edit).
  2. Скопируйте блок одного сотрудника (от { до }), поставьте запятую после предыдущего блока и вставьте. Последний блок — без запятой.
{
  "slug": "ivan-petrov",
  "first_name": "Иван",
  "last_name": "Петров",
  "position": "Руководитель отдела продаж",
  "phone": "+7 701 123 45 67",
  "email": "i.petrov@example.com",
  "website": "",
  "address": "",
  "links": [
    { "title": "WhatsApp", "url": "https://wa.me/77011234567" }
  ]
}
  1. Нажмите Commit changes. Через 1–2 минуты сайт обновится.

Поля: - slug — постоянная часть ссылки: латиницей, строчными, через дефис. Если оставить пустым, она создастся из имени автоматически, но лучше задавать вручную. - Пустое поле ("") на странице не показывается. website и address пустые → берутся общие значения из data/site.json (там можно указать сайт и адрес офиса компании). - links — дополнительные ссылки (WhatsApp, LinkedIn, Instagram…). Ссылка обязательно с https://. Если не нужны — []. - "hidden": true (добавить строкой в блок) — убрать визитку уволившегося сотрудника; её ссылка и QR перестанут работать.

Как сменить должность, телефон, e-mail и не потерять QR: меняйте только эти поля. Не меняйте slug — QR-код содержит адрес с ним. После смены имени, должности, телефона старые напечатанные QR продолжат работать, а страница покажет новые данные.

QR перестанут работать, если: изменить slug, удалить сотрудника из файла, переименовать репозиторий или аккаунт GitHub, удалить репозиторий. Поэтому имя репозитория выбирайте окончательно. Если когда-нибудь понадобится собственный домен (платный, не обязателен), ссылки придётся менять — для печати заранее решите, будете ли его использовать.

Где взять ссылку и QR нового сотрудника: - Ссылка: https://ИМЯ.github.io/cards/card/slug/ - QR (PNG): https://ИМЯ.github.io/cards/qr/slug.png, QR (SVG): .../qr/slug.svg - Все QR сразу архивом: вкладка Actions → последний запуск → внизу «Artifacts» → qr-codes (скачивается ZIP; хранится 90 дней, потом просто запустите сборку заново).

Этап 7. QR-коды для печати

  • SVG — векторный, лучший вариант для типографии: масштабируется без потери качества. Отдайте дизайнеру файл .svg каждого сотрудника.
  • PNG — 300 dpi, около 12,5 см по стороне; подходит для превью и офисной печати.
  • Свободное поле (quiet zone) 4 модуля уже включено в файл: не обрезайте белую рамку и не размещайте рядом текст и картинки.
  • Размер на визитке: сторона самого кода (без белой рамки) не менее 20 мм, лучше 22–25 мм; вместе с полем — около 25–30 мм.
  • Цвет: тёмный код на светлом фоне. На тёмно-синей визитке размещайте QR на белой плашке. Инвертированный (белый на синем) код, как сейчас на макете, читается не всеми приложениями — не используйте его для тиража без теста. Дизайнер может перекрасить модули в #00234A (контраст сохранится), но не в светлые оттенки.
  • Не добавляйте логотип в центр кода: адрес короткий, но запас прочности нужен для печати.
  • Новый QR ведёт на страницу визитки, а не в WhatsApp, как на текущем макете. Ссылку на WhatsApp добавьте в links (пример выше).
  • Всегда делайте тестовую печать и сканируйте до тиража.

Если что-то не работает

  • Красный запуск в Actions → прочитайте ошибку, исправьте employees.json, снова Commit.
  • Страница 404 сразу после первого запуска → подождите 2–3 минуты и обновите; убедитесь, что в Settings → Pages выбран источник GitHub Actions.
  • QR ведёт на ИМЯ.github.io/РЕПОЗИТОРИЙ — вы запускали сборку не на GitHub; QR создавайте только после публикации.
  • Смартфон не открывает контакт — отправьте мне описание модели и браузера.
